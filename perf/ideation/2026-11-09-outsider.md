## Framing arithmetic (the agent's, on the brief's numbers; none measured by it)
- Host bytes per token (32 + 53 + 9) x 9.5 MB = 0.89 GB = ~16 ms of DRAM time at 55 GB/s; the 28 ms host window is
  ~16 DRAM floor + ~7 NVMe wait + ~5 fixed per-layer cost.
- DRAM duty cycle 21 GB/s = 38% of the ceiling: saturated inside the host window, idle during the GPU's 14-17 ms.
  The idle window could carry 0.77-0.93 GB: about the whole host-served budget. Structural single-stream floor
  ~max(GPU-own, bytes / 55 GB/s) + the mispredicted quarter = 20-24 ms.
- One speculative copy per layer fits because floor(0.35 ms lead / 0.19 ms copy) = 1; a second spills into the host
  window and takes DRAM from the pool. A parallel DMA stream cannot help (link and DRAM are the same size): more
  copies need a longer lead, a source that is not DRAM, or preemptibility.
- Prefetch shortfall: 0.73 hits per layer x 9.5 MB / 55 GB/s = 0.126 ms per layer = ~5 ms per token expected, ~1 seen.
- The 0.45 ms "gap" is mostly GPU-own work (14-17 ms / 40 = 0.35-0.42 per layer); the residual is 1-4 ms per token.
  The host call hides more: critical lane ~0.36 + ~0.17 NVMe vs 0.7 measured = 5-7 ms per token of intercept.
- Serve: 5.2-6.0 GB per step = 550-630 records for 720 selections; a 12.2 GiB tier should leave ~320 host-served
  (~3.3 GB with NVMe double traffic): 2-2.7 GB per step (35-45%) unexplained.

2. SMT siblings pre-touch each pool thread's slice of the predicted pool record into its core's L2 during attention.

7. One persistent pull-model kernel per token (or per prefill layer) consuming a descriptor ring.
8. The loss is the host call's fixed intercept, not the gap: decompose by regression.
